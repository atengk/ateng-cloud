# 0001: 活跃分布式事务下 Sentinel 熔断降级强制 Fail-Fast 回滚架构

在微服务跨进程调用中，微服务治理框架（如 Alibaba Sentinel）常通过 Fallback 机制在发生网络超时或下游异常时返回兜底 Mock 假数据以保障可用性。然而，当该调用处于 Seata 活跃全局分布式事务（`RootContext.getXID() != null`）管控之下时，静默返回兜底数据将诱骗事务协调器（TC）误判业务链路成功并正常提交全局事务，导致上游提交、下游未落库的灾难性单边脏写资损。

`ateng-cloud-seata` 确立金融级降级防卫机制（`SeataFallbackDefense`）：在检测到活跃全局事务时，下游降级逻辑强制拦截并抛出受管业务异常（错误码 `5104`，`SEATA_DEGRADE_BLOCKED`），以确定性阻断事务假提交并触发两阶段全局原子回滚；仅在无分布式事务的普通调用链路中，才允许降级逻辑平滑放行并返回业务兜底数据。
